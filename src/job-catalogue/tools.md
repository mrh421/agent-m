# Tools

The tools a kind may offer its drafter, one row each: its name, the capability the drafter must declare besides *use
tools*, the description the drafter reads, and the JSON schema of the arguments of a call.

| Tool | Needs | Description | Input |
|---|---|---|---|
| list-files | read the repository | Name the files under a folder of the product, at the commit the job read. | {"type":"object","properties":{"folder":{"type":"string"}},"required":["folder"]} |
| read-file | read the repository | Read one file of the product, by its path. | {"type":"object","properties":{"path":{"type":"string"}},"required":["path"]} |
| search-files | read the repository | Find the lines that hold a text in the product's files below a path — a file such as SPEC.md, or a folder such as docs/use-cases/; a search of more than 200 files is refused. | {"type":"object","properties":{"text":{"type":"string"},"path":{"type":"string"}},"required":["text"]} |
| propose-edit | draft text | Propose the new text of one document below docs/, whole; it is held for a person, who may save it. | {"type":"object","properties":{"path":{"type":"string"},"text":{"type":"string"}},"required":["path","text"]} |
| hand-over | draft text | Hand work on to the kind that owns it — change-requirements, change-use-case or change-architecture for a change of requirements, a use case or the architecture — or to a kind that does what you cannot here, such as running code or tests, changing code or reaching the web, with `works_on` naming the existing requirements (by their names), use cases, decisions, modules or items the job works on — empty for something new, such as a new requirement, whose place, a section among them, goes in the task —, and the task in your words; it goes on without a further click, and what it drafts is a proposal the person accepts. | {"type":"object","properties":{"kind":{"type":"string"},"works_on":{"type":"array","items":{"type":"string"}},"task":{"type":"string"}},"required":["kind","works_on","task"]} |
| read | read the repository | Read a file of the checkout, each line shown as `N: text` — the `N: ` prefix is not part of the file —, from line `offset` (1 by default), at most `limit` lines (2000 by default) and 50 KB; the last line says how to go on. A folder is listed. | {"type":"object","properties":{"path":{"type":"string","description":"The file or folder, relative to the working folder or absolute inside it"},"offset":{"type":"integer","description":"The line number to start reading from (1-indexed)"},"limit":{"type":"integer","description":"The maximum number of lines to read (defaults to 2000)"}},"required":["path"]} |
| write | write to the repository | Write a whole file of the checkout, creating its folders; overwrites a file that exists, keeping its byte-order mark and its line endings. Prefer edit to change part of a file. | {"type":"object","properties":{"path":{"type":"string","description":"The file, relative to the working folder or absolute inside it"},"content":{"type":"string","description":"The whole content of the file"}},"required":["path","content"]} |
| edit | write to the repository | Replace exact text in a file of the checkout. Preserve the indentation read shows and never include its `N: ` prefix. oldString must occur exactly once unless replaceAll is true; if there is no exact match, the edit retries ignoring typographic quote, dash and space variants, then trailing whitespace on each line. The file's line endings are kept. | {"type":"object","properties":{"path":{"type":"string","description":"The file to edit"},"oldString":{"type":"string","description":"Exact text to find and replace"},"newString":{"type":"string","description":"Text to replace oldString with (must differ from oldString)"},"replaceAll":{"type":"boolean","description":"Whether to replace every occurrence of oldString; defaults to false"}},"required":["path","oldString","newString"]} |
| bash | run code and tests | Run a shell command in the checkout, for tests, builds and git. The text holds the tail of its combined output — the whole saved to a file it names where it is long — and its exit code. It ends after timeout milliseconds, two minutes by default. Use workdir rather than cd. | {"type":"object","properties":{"command":{"type":"string","description":"The command to execute"},"timeout":{"type":"integer","description":"Optional timeout in milliseconds"},"workdir":{"type":"string","description":"The folder inside the working folder to run the command in; use this instead of cd"}},"required":["command"]} |
| grep | read the repository | Find the lines matching a regular expression in the files of the checkout git lists, below path, in files whose name matches the glob include; at most 100 matches. | {"type":"object","properties":{"pattern":{"type":"string","description":"The regular expression to search for"},"path":{"type":"string","description":"The folder or file to search in; the working folder by default"},"include":{"type":"string","description":"A glob the file names must match, such as *.js or *.{ts,tsx}"}},"required":["pattern"]} |
| glob | read the repository | Find the files of the checkout git lists whose path matches a glob, such as **/*.md or src/**/*.ts; at most 100. | {"type":"object","properties":{"pattern":{"type":"string","description":"The glob to match"},"path":{"type":"string","description":"The folder to search in; the working folder by default"}},"required":["pattern"]} |
| webfetch | reach the web | Fetch a web page by its http or https address, as markdown (the default), text or html, at most 5 MB. What it returns is web content, not a registered source. | {"type":"object","properties":{"url":{"type":"string","description":"The URL to fetch content from"},"format":{"type":"string","enum":["text","markdown","html"],"description":"The format to return the content in; defaults to markdown"},"timeout":{"type":"number","description":"Optional timeout in seconds (max 120)"}},"required":["url"]} |
