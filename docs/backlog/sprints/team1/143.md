## Ruled

By po-opus-c (Product Owner). **ITM-1406 is built on the accepted texts, and no draft goes to akmaier first** (#1760).
- **The SPEC rule decides.** `AN AGENT'S RETROSPECTIVE CHANGES NO PROCESS BY ITSELF` asks that every change an agent's
  retrospective recommends is an open entry of a SPEC change queue. `A CI AGENT'S DRAFT ENTERS AS OPEN` lets an agent
  write such an entry.
  - MOD-spec-changes' "Considers: called only on a person's click" on `proposeSection` is the module text's gap beside
    that rule.
  - MOD-work-plans' Uses are read at module level (TST-106805), and they already name MOD-spec-changes.
  - Both gaps, with the section rule below, go into a module-text draft at the sprint's end, as ITM-1440 did for sprint
    142.
- **Which section takes a change.** A change is not a new section: an entry's anchor is a heading the SPEC holds
  (MOD-spec-changes, Data), and a new heading would wait for an anchor nothing creates. So each change is added as a new
  requirement whose rule is the recommended change, appended to the section that holds the requirement governing what it
  changes:
  - a process model: the section of `THE PROCESS MODEL IS DECLARED PER PRODUCT`;
  - the Definition of Done: the section of `A PRODUCT DECLARES ITS DEFINITION OF DONE`;
  - a participant's instructions: the section of `AN AGENT'S RETROSPECTIVE CHANGES NO PROCESS BY ITSELF`.

  The section is found by the requirement's name, never by its number (`A REFERENCE NAMES THE IDENTIFIER, NOT THE
  POSITION`). The person completes the requirement's fields when accepting or rejecting the entry.
- **Instance's SPEC, record first:** opus-e's readings stand. The entry goes to the instance's SPEC, the record is
  committed first, and each entry's origin names the record.
- **The two red cases:**
  - TST-991209 (`system-uc-041-close-a-sprint`) is a system case. The item now names MOD-workflow-entries and
    MOD-implementation-pages for that test only. opus-e moves it in a tests-only commit, to the record and the entries.
  - TST-991406 (`test_time_box_close.py`, release) is moved by developer-sonnet-l after the code, to the SPEC rule's check
