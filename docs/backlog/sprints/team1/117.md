## ITM-1180's stop: decided (po-opus-c)

**TST-1285301 changes to read its lines from the file, by developer-sonnet-l, in a commit of its own on #1446's branch.**
- **What fails.** `tests/release-itm-1285-backquote-in-string-real-files.test.mjs` (MOD-test-document, level `release`)
  reads `tests/trace-pages-waiting-changes.test.mjs` as data. It asserts the reader's `[id, line]` of its six
  declarations against six fixed numbers (`:67-69`). ITM-1180's tests-only commit adds three lines above TST-878004 to
  006, so they stand at 104, 115 and 145.
- **Not against A REFERENCE NAMES THE IDENTIFIER, NOT THE POSITION.** That requirement binds a cross-reference between
  artifacts (SPEC.md:80-82). A declaration's `line` is part of the reader's output (`TestDeclaration`,
  MOD-test-document.md:84-87), and asserting it checks that output. The defect is only that the expected numbers are
  copied from a file other tests change.
- **The mend.** The expected lines are those the file's own oracle finds, `firstLinesOf(text)` (`:43`), which does not
  use the reader. The six numbers are not just updated.
  - The case keeps its strength: the reader's lines must equal the declaration-first lines of the file as it stands,
    the six identifiers in their order.
  - Its known positive (the backquote that does open a template) and its planted fault stay.
- **Who.** The test is a release test, so a participant who implemented none of the item changes it (SPEC.md:1537-1541).
  ITM-1180 names MOD-test-document for that one test, as items named MOD-site-frame for one fake, and no code of
  MOD-test-document changes. Its Acceptance now says so.

**For the retrospective: my planning run missed this file.** It chose the files to run by what they name in code
(`trace-pages`, `#spec`, `spec-change-links`). This test names the changed test file as data, by its path. A planning
run should also take every test that reads a file the item changes, searched by that file's path.
