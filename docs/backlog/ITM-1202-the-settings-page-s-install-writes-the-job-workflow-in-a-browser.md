# ITM-1202 The Settings page's Install writes the job workflow in a browser

**REGISTER**

## Outcome

The Settings page's *Install* of Agent M's job workflow calls MOD-runtimes' `jobWorkflowFiles`. In a browser that throws:
`src/runtimes/ci.mjs:234`, "MOD-runtimes: the job workflow's templates are read in Node; a browser cannot read them yet".
- The templates are `src/runtimes/workflow/github.yml` and `gitlab.yml` (MOD-runtimes' Parts). `templateAt`
  (`ci.mjs:79-82`) reads them from the disk in Node and gives `null` in a browser.
- The comment there gives the reason: a fetch of the module's own data file is allowed by the check NO SERVER
  (`tests/test_no_backend.py`) only for a module it lists, and it does not list MOD-runtimes.
- So every installed `agent-m-jobs.yml` of the last two days was generated in Node by hand (`5008e0f4`, `709173aa`,
  `b1e499c7`), and the one click of `ONE CLICK PER DECISION` does not work on the page.

**First task:** read whether MOD-runtimes' text says how the templates reach a browser — a fetch of the data file, or the
templates held in a module file — and whether `tests/test_no_backend.py`'s list may name MOD-runtimes by that text. Where
the texts give it, build it and name the reading. Where they do not, the item stops for a draft to akmaier.

## Acceptance

- `jobWorkflowFiles` gives the same files in a browser as in Node, for GitHub and GitLab; a test compares both on one
  fixture.
- The check NO SERVER still passes, with no exception the texts do not give.
- The first commit holds only the tests, and CI is red on it.
